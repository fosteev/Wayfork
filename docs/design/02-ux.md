# UX

Menu bar app (`LSUIElement`), no Dock icon. Visual reference: approved
[prototype/variant-b.html](prototype/variant-b.html) (popover, sidebar Settings, grouped rules);
[prototype/index.html](prototype/index.html) is the rejected v1 kept for the Logs window,
helper alert and Add VLESS sheet, which are unchanged.

Surfaces: the menu bar **popover**, the **Settings** window, the **Logs** window, plus a few
sheets and alerts.

## Menu bar icon

Custom template asset (fork-in-the-road glyph), four variants:

| Global state | Icon | Notes |
|--------------|------|-------|
| off          | outline | |
| starting / stopping | filled, `.symbolEffect(.pulse)` | |
| on           | filled | |
| degraded     | filled, one branch hollow | tooltip names the failing tunnel |
| error        | outline + exclamation | |

Click opens the popover (`MenuBarExtra` with `.window` style: a borderless window anchored
under the icon, closes on click outside or Esc).

## Popover

320 pt wide, vertical stack, follows system appearance (light/dark):

```
[icon] Wayfork                                   [toggle]
       On — routing 6 domains through 2 tunnels
────────────────────────────────────────────────
┌ ● Work                       OpenVPN      [↻] ┐
│   connected · 10.8.0.6 on utun101 · 3 rules   │
└───────────────────────────────────────────────┘
┌ ● Home                       VLESS            ┐
│   ready · host.example.com · 2 rules          │
└───────────────────────────────────────────────┘
┌ ◐ Lab                        OpenVPN      [↻] ┐
│   connecting… attempt 2 · tls-error           │
└───────────────────────────────────────────────┘
┌ ○ Test                       VLESS   [Enable] ┐   (dimmed)
│   disabled · 1 rule                           │
└───────────────────────────────────────────────┘
────────────────────────────────────────────────
[ Route domain…            ] [Work ▾]  [Add]
────────────────────────────────────────────────
Settings ⌘,    Logs ⌘L                  Quit ⌘Q
```

- **Header**: glyph, name, global toggle. Toggle is disabled while starting/stopping (icon
  pulses). Summary line by state:
  - off: "Off — all traffic goes direct"
  - starting: "Starting…"
  - on: "On — routing N domains through M tunnels" ("On — no tunnels" when none enabled)
  - degraded: "Degraded — <tunnel> is failing · N domains, M tunnels up"
  - error: "Routing engine failed — see Logs"
- **Tunnel cards**, one per tunnel in store order. Line 1: status glyph, name, type badge,
  action button. Line 2 (secondary, 11 pt): state details.
  - connected: `connected · <ip> on <utun> · N rules`, action ↻ (reconnect)
  - ready (VLESS): `ready · <host> · N rules`, no action
  - connecting/reconnecting: `connecting… attempt N · <reason>`, action ↻
  - failed: reason in red (`failed: server rejected username/password`), action ✎ (opens
    Settings › Tunnels with that tunnel expanded and the offending field focused)
  - disabled: card dimmed, `disabled · N rules`, action **Enable**
  - global off: every card dimmed, `not running · N rules`, no actions
  Clicking a card body opens Settings › Tunnels with that tunnel expanded.
- **Quick add**: domain field (prefilled from the clipboard when it looks like a URL/host),
  tunnel popup (last used), Add. Match type is `suffix`; a `*` in the input switches to
  `wildcard`. Invalid input → red outline + one-line error under the field. Existing pattern
  → button reads **Update**. Applies immediately (hot reload). Hidden while global off.
- **Footer**: Settings, Logs, Quit as text buttons with shortcuts.
- Status glyphs: green filled (connected/ready), grey hollow (disabled/not running), orange
  half (connecting/reconnecting), red cross (failed).

## Settings window

Single window "Wayfork Settings", 820×560, resizable. Left sidebar (180 pt) with
**Tunnels · Rules · General**; content area with a large section title.

### Tunnels

```
Tunnels                                                  [+ Add ▾]
┌──────────────────────────────────────────────────────────────────┐
│ ● Work   OpenVPN  connected · vpn.example.com:1194 udp …  [●] ▸  │
│    Name       [ Work            ]                               │
│    Username   [ alice           ]                               │
│    Password   [ •••••••••       ]                               │
│    DNS        (•) Automatic (10.8.0.1)  ( ) Custom [        ]   │
│    Config     Aug 25, 2026 · ab12…9f3e   [Replace…]             │
│               3 rules · Show          [Reconnect]  [Delete…]    │
├──────────────────────────────────────────────────────────────────┤
│ ● Home   VLESS    ready · host.example.com:443 · REALITY   [●] ▸ │
├──────────────────────────────────────────────────────────────────┤
│ ✕ Lab    OpenVPN  failed: server rejected username/password [●] ▸│
├──────────────────────────────────────────────────────────────────┤
│ ○ Test   VLESS    disabled · host2.example.com:443        [○] ▸  │
└──────────────────────────────────────────────────────────────────┘
```

- Rows: status glyph, name, type badge, one-line summary, enabled toggle, chevron. Clicking
  a row expands it in place (one expanded at a time); the toggle works without expanding.
- Expanded OpenVPN: Name, Username/Password (only when `needsCredentials`), Key passphrase
  (only when `needsKeyPassphrase`), DNS (Automatic with the discovered address / Custom),
  Config (import date, short hash, Replace…), footer with rule count link, Reconnect,
  Delete….
- Expanded VLESS: Name, URL (UUID masked, Copy, Replace URL…), footer with rule count link
  and Delete….
- **+ Add** menu: *Import OpenVPN Config…* (file picker), *Add VLESS from URL…* (sheet).
  Dropping a `.ovpn` file anywhere on the window imports it.
- Edits save on focus loss / toggle. While running: credentials/config change → reconnect
  that tunnel; enable/disable → routing restart; name → nothing.
- Delete with rules attached: "Delete tunnel and its N rules?" — rules go with it.

**Add VLESS sheet**: text field prefilled from the clipboard when it starts with
`vless://`; live parse preview (Name, Server, Security, Transport); Add enabled only when
valid; parse/unsupported errors inline in red.

### Rules

```
Rules                                        [🔍 Search domains   ]
┌ ● Work   OpenVPN   3 rules                              [+] ┐
│ [✓] example.com                Suffix                    ⋮⋮ │
│ [✓] api.internal.example.com   Exact                     ⋮⋮ │
│ [ ] old.example.com            Exact     paused          ⋮⋮ │
└─────────────────────────────────────────────────────────────┘
┌ ● Home   VLESS     2 rules                              [+] ┐
│ [✓] *.cdn.example.com          Wildcard                  ⋮⋮ │
│ [✓] news.example.org           Suffix                    ⋮⋮ │
└─────────────────────────────────────────────────────────────┘
┌ ○ Test   VLESS     1 rule                               [+] ┐   (dimmed)
│ [✓] docs.example.net           Suffix   tunnel disabled — goes direct │
└─────────────────────────────────────────────────────────────┘
```

- One group per tunnel, in store order; groups of disabled tunnels are dimmed.
- Row: enabled checkbox, pattern (monospace, inline-editable), match popup, note, drag
  grip. `+` in the group header adds an empty row in edit mode; Enter commits, Esc
  discards; Delete key removes the selected row.
- Drag within a group reorders; drag to another group moves the rule to that tunnel.
- A pattern that also appears in an earlier group gets a **shadowed** chip with a tooltip
  ("`example.com` is already routed via Work"); a pattern covering a tunnel's own server
  host gets a **warning** chip.
- Search filters rows across groups; empty groups collapse to their header.
- Empty state: "No rules yet. Everything goes direct. Add a rule here or from the menu bar."
- Changes apply live; a rejected change shows an inline error under the group.

### General

Grouped forms: Startup (Launch at login, Connect on launch), Reliability (Reconnect
automatically, Notify when a tunnel fails), DNS (Direct traffic resolver: System / Custom),
Logs (Level, Keep logs for N days, Open Logs Folder), Helper & About (helper status with
Reinstall / Open System Settings… / Install Helper depending on state; version line;
Export Diagnostics…).

## Logs window

Separate window (⌘L), 900×500. Toolbar: source filter (All / App / Daemon / sing-box /
each tunnel), level filter (Error / Warning / Info / Debug), search field, Follow toggle,
Clear, Copy. Monospaced list, newest at the bottom, auto-scroll while Follow is on. Lines:
`HH:mm:ss.SSS  source  LEVEL  message`. Detail in [06-logging.md](06-logging.md).

## First run and helper approval

First **Turn On**:

1. App calls `SMAppService.daemon(...).register()`.
2. Status `.requiresApproval` → alert:
   > **Allow Wayfork to run in the background.** Wayfork needs a helper with system
   > privileges to create the tunnel interface. Open System Settings → Login Items and
   > enable Wayfork under "Allow in the Background". Wayfork continues automatically once
   > it's enabled.
   > [Open System Settings] [Cancel]
   The app polls status every second and proceeds automatically once `.enabled`.
3. macOS may ask for an administrator password on that toggle if the account is not an
   admin; Wayfork itself never prompts for a password.

## Notifications

`UserNotifications`, opt-out in General: tunnel entered `failed` (permanent), routing
engine crashed / could not start, helper lost approval. Never for transient reconnects.

## Error catalogue

| Code | When | User message | Recovery offered |
|------|------|--------------|------------------|
| `helper.notApproved` | register() → requiresApproval | see alert above | Open System Settings |
| `helper.versionMismatch` | handshake | "Updating helper…" (silent) | auto re-register; on failure: Reinstall Helper |
| `helper.unreachable` | XPC invalidated | "Can't reach the Wayfork helper." | Retry / Reinstall Helper |
| `singbox.configInvalid` | `sing-box check` failed | "Routing config rejected: <first line>". Should not happen with generated configs; include in diagnostics | Export Diagnostics |
| `singbox.startFailed` | exit within 3 s / 3 crashes | "Routing engine failed to start. Another VPN may be active." | Show Log |
| `ovpn.authFailed` | `>PASSWORD:Verification Failed` | card: "failed: server rejected username/password" | ✎ → credentials |
| `ovpn.keyPassphrase` | private key decrypt failed | card: "failed: wrong key passphrase" | ✎ → passphrase |
| `ovpn.configError` | openvpn exits with options error | card: "failed: OpenVPN rejected the config" + line in Logs | ✎ → Replace Config |
| `ovpn.unreachable` | RECONNECTING loop > 2 min | card stays "reconnecting… attempt N · <reason>" | ↻ / Logs |
| `import.ovpn.missingFiles` | referenced files absent | "ca.crt, client.key referenced but not found next to the .ovpn" | pick folder / cancel |
| `import.ovpn.unsupported` | e.g. `dev tap` | "TAP configs are not supported." | — |
| `import.vless.invalid` | parse error | "Not a valid vless:// URL: <reason>" | — |
| `import.vless.unsupported` | e.g. `headerType=http`, transport `kcp` | "Transport \"kcp\" is not supported yet." | — |
| `rule.invalid` | validation | inline: "Not a valid domain" / "`*` only allowed in wildcard rules" | — |
| `store.corrupt` | load | "Settings file was unreadable and has been reset. A backup is at …" | Reveal in Finder |
