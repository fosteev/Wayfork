# UX

Menu bar app (`LSUIElement`), no Dock icon. Visual reference: approved
[prototype/variant-b.html](prototype/variant-b.html) (popover, sidebar Settings, grouped rules);
[prototype/index.html](prototype/index.html) is the rejected v1 kept for the Logs window,
helper alert and Add VLESS sheet, which are unchanged.

Surfaces: the menu bar **popover**, the **Settings** window, the **Logs** window, plus a few
sheets and alerts.

## Menu bar icon

Custom template asset (fork-in-the-road glyph), four variants:

| Global state | Icon | Notes |
|--------------|------|-------|
| off          | outline | |
| starting / stopping | filled, `.symbolEffect(.pulse)` | |
| on           | filled | |
| degraded     | filled, one branch hollow | tooltip (`.help`) carries the summary line, which names the failing tunnel |
| error        | outline + exclamation | |

Click opens the popover (`MenuBarExtra` with `.window` style: a borderless window anchored
under the icon, closes on click outside or Esc).

## Popover

320 pt wide, vertical stack, follows system appearance (light/dark):

```
[icon] Wayfork                                   [toggle]
       On — routing 6 domains through 2 tunnels
────────────────────────────────────────────────
┌ ● Work      OpenVPN   ↓ 1.2 MB/s ↑ 85 KB/s [↻] ┐
│   connected · 10.8.0.6 on utun101 · 3 rules   │
└───────────────────────────────────────────────┘
┌ ● Home      VLESS      ↓ 0 B/s ↑ 0 B/s        ┐
│   ready · host.example.com · 2 rules          │
└───────────────────────────────────────────────┘
┌ ◐ Lab                        OpenVPN      [↻] ┐
│   connecting… attempt 2 · tls-error           │
└───────────────────────────────────────────────┘
   Direct                  ↓ 200 KB/s ↑ 12 KB/s
────────────────────────────────────────────────
[ Route domain…            ] [Work ▾]  [Add]
────────────────────────────────────────────────
Settings ⌘,    Logs ⌘L                  Quit ⌘Q
```

- **Header**: glyph, name, global toggle. Toggle is disabled while starting/stopping (icon
  pulses). Summary line by state:
  - off: "Off — all traffic goes direct"
  - starting: "Starting…"
  - on: "On — routing N domains through M tunnels" ("On — no tunnels" when none enabled);
    with a default tunnel (F8): "On — everything via <tunnel> · N rules, M exceptions"
  - degraded: "Degraded — <tunnel> is failing · N domains, M tunnels up"; when the failing
    tunnel is the default: "Degraded — <tunnel> (default) is down · unmatched traffic is
    blocked"
  - error: "Routing engine failed — see Logs"
- **Tunnel cards**, one per *enabled* tunnel in store order (changed 2026-08-25: disabled
  tunnels are not listed — they live in Settings › Tunnels, which shows everything; when
  every tunnel is disabled the list is replaced by "All tunnels are disabled." with a
  "Manage tunnels…" button). Line 1: status glyph, name, type badge, action button.
  Line 2 (secondary, 11 pt): state details.
  - connected: `connected · <ip> on <utun> · N rules`, action ↻ (reconnect); the default
    tunnel (F8) appends `· everything else`
  - ready (VLESS): `ready · <host> · N rules`, no action
  - connecting/reconnecting: `connecting… attempt N · <reason>`, action ↻
  - failed: reason in red (`failed: server rejected username/password`), action ✎ (opens
    Settings › Tunnels with that tunnel expanded and the offending field focused)
  - global off: every card dimmed, `not running · N rules`, no actions
  Clicking a card body opens Settings › Tunnels with that tunnel expanded.
- **Traffic rates (F9)**, while the global state is on/degraded. Line 1 of a connected or
  ready card gets `↓ <rate> ↑ <rate>` between the type badge and the action button
  (11 pt, secondary, monospaced digits; dimmed to tertiary when both are 0). Not shown for
  connecting / reconnecting / failed cards or while off/starting/stopping. After the cards a
  slim **Direct** row (no card background, no action, not clickable) shows the rate of
  traffic that bypasses the tunnels; with a default tunnel (F8) that is exceptions and
  local names only, and the row is labelled `Direct · exceptions`. Hovering a rate shows
  `Since Turn On: ↓ 1.2 GB ↑ 88 MB · 14 connections`. Rate formatting: `ByteCountFormatter`
  decimal units with at most three significant digits plus `/s` (`0 B/s`, `85 KB/s`,
  `1.2 MB/s`, `12 MB/s`); totals the same without `/s`. Figures update once a second; when
  no sample has arrived for 3 s (daemon busy, Clash API down) the labels show `—` instead
  of stale numbers. The header summary is unchanged — each exit (every tunnel and Direct)
  carries its own figure exactly once, so a total is not repeated.
- Implementation notes (2026-08-25, F9): the strings come from `TrafficFormat`
  (`WayforkCore`), hand-rolled rather than `ByteCountFormatter` so tests and layout are
  locale-independent: one decimal below 10 (`1.0 KB`, `9.9 MB`), none above (`12 MB`,
  `999 KB`), `999.5` rolls over to the next unit, units stop at PB. The rate is right-aligned
  before the action button (the name truncates first). The Direct row appears only while
  on/degraded; the placeholder `↓ — ↑ —` carries the tooltip "No traffic sample in the last
  3 seconds". Staleness is a 3 s timer in `AppModel` re-armed by every sample; Off, a helper
  interruption and an engine that is not running clear the figures at once. A sample that
  arrives while the app is not `desiredOn` is ignored.
- **Dead-UDP hint (H3, 2026-09-01)**: when a tunnel's counters report one-way UDP flows
  (`oneWayUDPFlows > 0` — sent for ≥ 10 s, received nothing; docs/design/05-daemon.md,
  "Traffic sampling"), an orange ⚠ appears between the rate and the action button on that
  card, tooltip "N UDP connections sent data but received nothing for 10 s — the server may
  be dropping UDP" (`TrafficFormat.oneWayUDPHint`). Shown only where the rate itself is
  shown; the Direct row never carries it (a one-way UDP flow to the open internet says
  nothing about a tunnel server). The same counts land in the diagnostics `system.txt`.
- **Quick add**: domain field (prefilled from the clipboard when it looks like a URL/host),
  tunnel popup (last used; last item **Direct** adds an exception, F8), Add. Match type is `suffix`; a `*` in the input switches to
  `wildcard`, an IPv4 address or subnet to `ip` (F11). Invalid input → red outline + one-line error under the field. Existing pattern
  → button reads **Update**. Applies immediately (hot reload). Hidden while global off.
- **Footer**: Settings, Logs, Quit as text buttons with shortcuts.
- Empty store: the cards are replaced by "No tunnels yet" with an "Add a tunnel…" button
  that opens Settings › Tunnels; quick add is hidden until a tunnel exists.
- Status glyphs: green filled (connected/ready), grey hollow (disabled/not running), orange
  half (connecting/reconnecting), red cross (failed).

## Settings window

Single window "Wayfork Settings", 820×560, resizable. Left sidebar (180 pt) with
**Tunnels · Rules · General**; content area with a large section title.

### Tunnels

```
Tunnels                                                  [+ Add ▾]
┌──────────────────────────────────────────────────────────────────┐
│ ● Work   OpenVPN  connected · vpn.example.com:1194 udp …  [●] ▸  │
│    Name       [ Work            ]                               │
│    Username   [ alice           ]                               │
│    Password   [ •••••••••       ]                               │
│    DNS        (•) Automatic (10.8.0.1)  ( ) Custom [        ]   │
│    Config     Aug 25, 2026 · ab12…9f3e   [Replace…]             │
│               3 rules · Show          [Reconnect]  [Delete…]    │
├──────────────────────────────────────────────────────────────────┤
│ ● Home   VLESS    ready · host.example.com:443 · REALITY   [●] ▸ │
├──────────────────────────────────────────────────────────────────┤
│ ✕ Lab    OpenVPN  failed: server rejected username/password [●] ▸│
├──────────────────────────────────────────────────────────────────┤
│ ○ Test   VLESS    disabled · host2.example.com:443        [○] ▸  │
└──────────────────────────────────────────────────────────────────┘
```

- Rows: status glyph, name, type badge, one-line summary, enabled toggle, chevron. Clicking
  a row expands it in place (one expanded at a time); the toggle works without expanding.
- Expanded OpenVPN: Name, Username/Password (only when `needsCredentials`), Key passphrase
  (only when `needsKeyPassphrase`), DNS (Automatic with the discovered address / Custom),
  Config (import date, short hash, Replace…), footer with rule count link, Reconnect,
  Delete….
- Expanded VLESS: Name, URL (UUID masked, Copy, Replace URL…), footer with rule count link
  and Delete….
- Both kinds (F8): a toggle **Route everything else through this tunnel** above the footer.
  Turning it on moves the default from whichever tunnel had it (only one); the row summary
  gets `· everything else`. Hint under the toggle: "Domains without a rule use this tunnel;
  add exceptions in Rules › Direct. While it is down, unmatched traffic is blocked." If the
  default tunnel is disabled the hint turns orange: "Disabled — everything else goes direct."
- **+ Add** menu: *Import OpenVPN Config…* (file picker), *Add VLESS from URL…* (sheet).
  Dropping a `.ovpn` file anywhere on the window imports it.
- Edits save on focus loss / toggle. While running: credentials/config change → reconnect
  that tunnel; enable/disable → routing restart; name → nothing.
- Delete with rules attached: "Delete tunnel and its N rules?" — rules go with it.

**Add VLESS sheet**: text field prefilled from the clipboard when it starts with
`vless://`; live parse preview (Name, Server, Security, Transport); Add enabled only when
valid; parse/unsupported errors inline in red.

### Rules

```
Rules                                        [🔍 Search rules     ]
┌ ● Work   OpenVPN   4 rules                              [+▾] ┐
│ [✓] example.com                Suffix                    ⋮⋮ │
│ [✓] ▣ Telegram                 App                       ⋮⋮ │
│ [✓] api.internal.example.com   Exact                     ⋮⋮ │
│ [ ] old.example.com            Exact     paused          ⋮⋮ │
└─────────────────────────────────────────────────────────────┘
┌ ● Home   VLESS     2 rules                              [+] ┐
│ [✓] *.cdn.example.com          Wildcard                  ⋮⋮ │
│ [✓] news.example.org           Suffix                    ⋮⋮ │
└─────────────────────────────────────────────────────────────┘
┌ ○ Test   VLESS     1 rule                               [+] ┐   (dimmed)
│ [✓] docs.example.net           Suffix   tunnel disabled — goes direct │
└─────────────────────────────────────────────────────────────┘
```

- One group per tunnel, in store order; groups of disabled tunnels are dimmed.
- F8: a **Direct** group sits above the tunnel groups (grey glyph, badge "exceptions"). Its
  header hint reads "Everything else goes through <tunnel>; these domains stay direct" when
  a default tunnel is set, otherwise "Overrides tunnel rules; everything unmatched already
  goes direct". Rows, editing, drag & drop and search work like in tunnel groups; dragging a
  rule into it turns it into an exception. Local names (`.local`, `.lan`, `.internal`,
  `.home.arpa`) are always direct and listed as a non-editable footnote.
- Row: enabled checkbox, pattern (monospace, inline-editable), match popup, note, drag
  grip. `+` in the group header adds an empty row in edit mode; Enter commits, Esc
  discards; Delete key removes the selected row.
- Drag within a group reorders; drag to another group moves the rule to that tunnel.
- A pattern that also appears in an earlier group gets a **shadowed** chip with a tooltip
  ("`example.com` is already routed via Work", or "… is an exception" when the Direct
  group has it); a pattern covering a tunnel's own server
  host gets a **warning** chip.
- Search filters rows across groups; empty groups collapse to their header.
- Empty state: "No rules yet. Everything goes direct. Add a rule here or from the menu bar."
- Changes apply live; a rejected change shows an inline error under the group.
- F10: the `+` in a group header is a menu — **Domain** (empty row in edit mode, as before)
  or **Application…** (open panel limited to application bundles, starting in
  `/Applications`). An application row shows the app icon and display name instead of a
  pattern, the bundle path as tooltip and a fixed "App" label instead of the match popup;
  checkbox, note, drag & drop and the shadowed chip work as for domains. A bundle that no
  longer exists gets a **not found** chip ("`/Applications/Foo.app` is missing; the rule
  matches again once it is back"). Search matches app names and paths. Quick add in the
  menu bar has no application entry.
- F11: the pattern field also takes an IPv4 address or subnet (`10.8.0.0/24`); the match
  popup gains **IP** and switches to it on its own while typing, the placeholder reads
  `example.com or 10.0.0.0/24`, search matches addresses, and quick add accepts IPs. A
  rule that overlaps one of the Mac's own networks gets a **warning** chip ("covers your
  LAN (en0, 192.168.1.0/24); devices in it go through the tunnel while Wayfork is on").
  No file dialog and no extra menu item: an IP is typed where a domain is.
- Implementation notes (2026-08-25, F10): app rows have no inline edit — the context menu
  offers **Reveal in Finder** instead of Edit (delete and re-add to change the app); the
  match popup lists only the domain kinds (`RuleMatch.domainCases`). The `.app` suffix is
  checked case-insensitively, the stored path keeps its case. A path typed into the domain
  field fails as "Enter a domain" (URL-part stripping leaves nothing) — app rules come
  only through the dialog. Icon / display name / existence are cached per path on the main
  actor (`AppBundleInfo`).
- Fake IPs (2026-08-26): an address in `198.18.0.0/15` seen in the logs is one sing-box
  handed to a *name* and routes by that name, so a rule on it could never match. Pasting
  one into any pattern field (Rules, inline editor, quick add) replaces it on the spot
  with the wildcard of the name's domain — `198.18.0.118` that was issued to
  `gitlab.example.com` becomes `*.example.com` (a two-label name stays as a suffix rule, a
  name right under `co.uk`-style suffixes stays exact); the app log notes the swap. The
  names come from sing-box's `dns: exchanged A … IN A 198.18.x.x` lines (`FakeIPIndex`,
  rebuilt from the log tail at launch, so nothing is known at `warn` log level); a fake IP
  the logs have not explained fails with "… is a fake IP Wayfork issued to a name it has
  not logged yet — add the domain instead".
- Implementation notes (2026-08-25, F11): while typing, `*` switches the popup to Wildcard
  and an address or subnet to IP; editing an IP back into a name returns to Suffix, Exact
  and Wildcard are otherwise left as chosen. The placeholder is `example.com or
  10.0.0.0/24` in both the new row and the inline editor; the popover field reads "Route
  domain or IP…". An IP typed under a domain kind fails with "This is an IP address — pick
  the IP match". The LAN chip is the generic **warning** chip with the interface and network
  in its tooltip; `AppModel` refreshes the interface list at most every 10 s.

### General

Grouped forms: Startup (Launch at login, Connect on launch), Reliability (Reconnect
automatically, Notify when a tunnel fails), DNS (Direct traffic resolver: System / Custom),
Logs (Level, Keep logs for N days, Open Logs Folder), Helper & About (helper status with
Reinstall / Open System Settings… / Install Helper depending on state; version line;
Export Diagnostics…), Backup (Export… / Import… of `wayfork-export.json`, see
[01-data-model.md](01-data-model.md); the sheets described there open from here).

## Logs window

Separate window (⌘L), 900×500. Toolbar: source filter (All / App / Daemon / sing-box /
each tunnel), level filter (Error / Warning / Info / Debug), search field, Follow toggle,
Clear, Copy. Monospaced list, newest at the bottom, auto-scroll while Follow is on. Lines:
`HH:mm:ss.SSS  source  LEVEL  message`. Detail in [06-logging.md](06-logging.md).
Implementation note: Follow is a manual toggle in MVP (macOS 14 SwiftUI has no reliable
scroll-position hook; auto-off on scroll-up is deferred).

## First run and helper approval

First **Turn On**:

1. App calls `SMAppService.daemon(...).register()`.
2. Status `.requiresApproval` → alert:
   > **Allow Wayfork to run in the background.** Wayfork needs a helper with system
   > privileges to create the tunnel interface. Open System Settings → Login Items and
   > enable Wayfork under "Allow in the Background". Wayfork continues automatically once
   > it's enabled.
   > [Open System Settings] [Cancel]
   The app polls status every second and proceeds automatically once `.enabled`.
3. macOS may ask for an administrator password on that toggle if the account is not an
   admin; Wayfork itself never prompts for a password.

## Notifications

`UserNotifications`, opt-out in General: tunnel entered `failed` (permanent), routing
engine crashed / could not start, helper lost approval. Never for transient reconnects.
The engine notification fires once per failure streak and says the app keeps retrying; the
retries themselves are silent (05-daemon.md, "Engine failure recovery").

## Error catalogue

| Code | When | User message | Recovery offered |
|------|------|--------------|------------------|
| `helper.notApproved` | register() → requiresApproval | see alert above | Open System Settings |
| `helper.versionMismatch` | handshake | "Updating helper…" (silent) | auto re-register; on failure: Reinstall Helper |
| `helper.unreachable` | XPC invalidated | "Can't reach the Wayfork helper." | Retry / Reinstall Helper |
| `singbox.configInvalid` | `sing-box check` failed | "Routing config rejected: <first line>". Should not happen with generated configs; include in diagnostics | Export Diagnostics |
| `singbox.startFailed` | startup verification fails twice / 3 crashes | "Routing engine failed to start. Another VPN may be active." | Show Log; the app re-applies on its own with backoff |
| `ovpn.authFailed` | `>PASSWORD:Verification Failed` | card: "failed: server rejected username/password" | ✎ → credentials |
| `ovpn.keyPassphrase` | private key decrypt failed | card: "failed: wrong key passphrase" | ✎ → passphrase |
| `ovpn.configError` | openvpn exits with options error | card: "failed: OpenVPN rejected the config" + line in Logs | ✎ → Replace Config |
| `ovpn.unreachable` | RECONNECTING loop > 2 min | card stays "reconnecting… attempt N · <reason>" | ↻ / Logs |
| `import.ovpn.missingFiles` | referenced files absent | "ca.crt, client.key referenced but not found next to the .ovpn" | pick folder / cancel |
| `import.ovpn.unsupported` | e.g. `dev tap` | "TAP configs are not supported." | — |
| `import.vless.invalid` | parse error | "Not a valid vless:// URL: <reason>" | — |
| `import.vless.unsupported` | e.g. `headerType=http`, transport `kcp` | "Transport \"kcp\" is not supported yet." | — |
| `rule.invalid` | validation | inline: "Not a valid domain" / "`*` only allowed in wildcard rules" / "Not a valid IP address or subnet" / "This is an IP address — pick the IP match" / "This range is reserved" | — |
| `store.corrupt` | load | "Settings file was unreadable and has been reset. A backup is at …" | Reveal in Finder |
