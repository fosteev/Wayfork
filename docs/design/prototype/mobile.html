Wayfork for phones

A first sketch of the mobile client, drawn before the Features phase so we can argue about the shape instead of a list. Android is drawn in full (Flutter, Material 3), iPhone only where it behaves differently. Names, sites and numbers are examples.

The model on a phone: the OS gives one VPN connection; inside it sing-box sends each site to a tunnel or straight out, exactly as on the Mac. Every tunnel kind sing-box carries natively works. OpenVPN does not.

Decisions drawn here

  1. Four tabs: Home (the popover), Sites (Rules), Tunnels, More (General, diagnostics). P1–P5
  2. Home opens with one big on/off and the same summary sentence as the Mac popover. Tunnel cards keep status, latency and sparkline; Recent keeps “Route via”. P1
  3. Routing a site you are looking at should not need typing: Wayfork is a Share target. Share a page from the browser and pick a tunnel. S3
  4. Tunnels arrive by QR code (what VPN panels show), by a link already on the clipboard, by subscription URL or file. A tunnel can be shown as a QR to move it to another phone. T2–T4
  5. A backup from the Mac or Windows imports as is. OpenVPN tunnels come in as Desktop only: listed, greyed, their sites go as usual on the phone. S1, T1
  6. Android keeps app rules (by package) and TCP/UDP only. iPhone has no app rules; the Apps filter is not there at all. S4, I3
  7. Outside the app: a persistent notification with rates and Turn off, a Quick Settings tile, and Android's Always-on VPN for start at boot. X1
  8. First run is four steps: add a tunnel, pick sites, allow the VPN, try it. F1–F4
  9. Russian from day one (switch above; captions stay English). It needs plural forms (1 сайт, 3 сайта, 6 сайтов), never declines a tunnel name the user typed (“Нидерланды: нет подключения”, not a case form), and formats numbers the Russian way (1,9 МБ/с). The desktop apps have no localisation yet. all

Not on the phone

  • OpenVPN: no per-tunnel processes on iOS, one TUN on both. Possible later only as an embedded OpenVPN 3 core; that is research, not a feature.
  • VLESS over XHTTP: needs its own xray process, same reason.
  • Local proxy port (F17), wayforkctl (F21), system resolver override (F12): no use or no hook on a phone. All phone DNS already goes through the VPN.
  • Full log viewer: More › Logs shows Problems only, plus Share diagnostics.

Open questions

  • Are a desktop-only tunnel's sites “as usual”, or do they go via the default tunnel when there is one? Drawn: as usual.
  • iPhone at all, given App Store rules for VPN apps (organisation account) and removals from the Russian store? TestFlight-only is the realistic floor.
  • Sync with the desktop app, or backup files only? Drawn: backup files and per-tunnel QR.

P · Home the popover, one tap from anywhere

S · Sites Rules, grouped by tunnel as in variant B/C

T · Tunnels add by QR, link, subscription or file

M · More General, diagnostics, backup

F · First run F22 in four steps

I · iPhone only the differences

Same screens and words in iOS controls. What changes: no app rules and no app names, the VPN lives in a Network Extension with about 50 MB of memory, and turning on at boot is iOS's Connect On Demand.
