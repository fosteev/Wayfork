Wayfork UI prototype — variant C

Redraw of the approved variant B for the F14–F18 wave (roadmap/next-features.md) with a first-time user in mind. Same architecture: popover dashboard under the menu bar, sidebar Settings with inline expansion, rules grouped by tunnel. New on the boards: latency with a sparkline on every card (F14), a Recent list that turns a domain into a rule in one click (F15), tunnel groups (F16), a local proxy port per tunnel (F17), a block-list switch (F18), and the Probe in rule testing. The friction audit that drove the changes is a comment at the top of this file. Popover is 360 px wide, Settings 720 × 480, macOS 14 look, no scripts.

Can't reach (F19) is a pane on top of the Logs window, not a new page: the question "what could my app not reach?" ends in the log anyway. One row per site + app — the site (domain, or ip:port when there was no name), the app that opened it, how many tries, why in the user's words (no answer · refused · blocked by your list · no such name · ‹tunnel› is down), the exit it went through, when last. Clicking a row filters the log below to that site — the search field takes the host, the level goes to All, and a line above the log says what is shown with Show all lines to go back. Row actions on hover: Route via ▾ (a suffix rule, as in Recent — the usual fix for a site that works only through a tunnel), Never block when the reason is the block list, × to dismiss. The popover gets one red line under the summary while anything failed in the last 5 minutes; Show opens this window. Rows live since Turn On (200 max, cleared on Turn Off). Callouts: at log detail Problems the app column is empty (sing-box prints the process only at info), and the empty state. Only connections that could not be established are listed — an HTTP 403 inside TLS is invisible and is not a failure here.

Connections by exit (F20 draft) is a second view of the Logs window, chosen by the Log · Connections segment in the toolbar — the Can't reach pane already lives there and both views answer the same "why doesn't it work?" question, so no new window. Opened from the popover footer (Connections ⇧⌘L), from Details on a tunnel card whose connections fail, and from the red line. One row per exit: every tunnel, every group (with the member it is using), Not via any tunnel (direct), and a dimmed Blocked by your list row that is shown for completeness but is excluded from the failure counts and the total. Columns: Connections (opened through the exit), Reached (sing-box opened them), Failed (sing-box could not — the F19 rows, summed), the fail rate with a bar (grey ≤ 1 %, amber ≤ 5 %, red above), the last failure's reason and time. Clicking an exit expands the F19 rows that went through it (site, app, tries, why, when), with Route via ▾ on hover — the fix is one click away, as everywhere else. Since Turn On · Last 5 min switches the window; Reset zeroes the counters. Numbers are connections, not requests: one page load is dozens, a keep-alive connection carries hundreds of requests — the rate is what to read, the counts only say how busy an exit is. Both counts come from the same sing-box log lines the F19 tracker already parses (inbound connection to = opened, ERROR … open connection = failed), so the numerator and the denominator never disagree; the Clash API is not used — it lists live connections only and misses everything shorter than a second. What happened inside a reached connection (HTTP status, a stalled download) is invisible and is not counted.
