Wayfork UI prototype — first-run guide (F22)

The guide a new user sees on the first launch, drawn in the variant C style (same tokens, popover and cards). Scope: ROADMAP.md › F22; stages: roadmap/first-run-guide.md. Six steps that do the real setup — welcome, allow the helper, add a tunnel, choose sites, turn on, try it — then a Getting started card in the popover. The decisions and open questions are a comment at the top of this file. Guide window 600 × 410, popover 360 px, macOS 14 look, no scripts.

Rail: six steps, the current one filled, finished ones ticked; a finished step can be clicked to go back and change it. Continue is disabled until the step is done — the helper step has no Continue at all, it moves on when macOS reports the helper enabled. Skip guide (any step) ends it for good; closing the window is not skipping (C12·c). Step 3 reuses the Add tunnel import and the F13 link parser; step 4 writes suffix rules through the same path as quick add; step 5 is the popover switch; step 6 reads the traffic sampler. Nothing in the guide is a second copy of an existing screen's logic.

Card sits on top of the popover so it is seen, and is gone for good when all three are ticked or on ×. Each line is ticked by doing the thing once, not by reading it: a rule added from the popover; the Can't reach pane opened; an app rule saved. Show me opens the place it names. Resume (c): the C2 No-tunnels state, reworded when the guide was left open-ended; Skip guide brings back the plain C2 text instead. Replay (d): the guide on top of an existing setup starts at step 3 with "Add another VPN" and adds, never replaces. Upgrading users with tunnels never see any of this.
