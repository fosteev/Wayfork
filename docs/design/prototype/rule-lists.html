Wayfork UI prototype — rule lists

A redraw of Settings › Rules. Today the page has one section per tunnel and per group, empty ones included, and moving “everything for Claude” to another exit means editing four rules one by one. Here the user groups rules by what they are for into lists (Claude, Telegram, Banks…), and each list has one Route via menu. Change it once and every site and app in the list moves. The same menu sits in the popover, so switching a list does not need Settings. Drawn in the variant C style (same tokens, window 720 px, popover 360 px, no scripts). Decisions and open questions are at the bottom.

R6 · Before and after, on the maintainer's setup (4 groups, 9 single tunnels)

Today — sections per exit
11 sections on the page, 7 of them No sites yet (every group member is listed). The Claude rules sit under germ 5.2 mixed with ip.net.coffee; moving them from singapure meant editing each row, one apply per edit (three applies in six seconds in the log on 2026-11-03). The default exit is a Default badge on one header.
With lists
4 lists (Claude, Telegram, IP check, Old rules) and the Everything else line. Tunnels without rules are not on this page. Moving Claude is one menu pick and one apply, from Settings or the popover. Existing rules are converted once into exit-named lists. Preserving existing TCP/UDP priority can require separate narrowed and broad lists per exit. Previously inactive rows remain intact in paused lists for review.

Decisions drawn here and open questions

  1. Name: “list”, not “rule group”: group already means a set of tunnels with failover (F16), and two kinds of group on one page would confuse. Alternatives: set, service, profile.
  2. Every rule belongs to exactly one list. A rule's exit = the list's exit unless the row pins its own (R5). No free-standing rules; adding a site from Recent or the popover asks for a list (default: the last one used).
  3. Order: lists routed Direct first (exceptions win, as today), then lists in the user's order, rows in list order. The shadowed check works across lists and names the winner.
  4. Paused list (switch off) = all its rules, including pins, are skipped; lower lists may match before Everything else. Same as unticking every row, but reversible in one click.
  5. Everything else is the old defaultTunnelID, moved to its own line. A list can point at it (“Same as Everything else”).
  6. Migration: exit-named lists in legacy priority order, splitting narrowed and broad rows when needed to preserve routing. Previously suppressed rows stay in visible paused lists; they can be enabled after review. Generated plan hashes can change; compatibility is checked by routing and DNS outcomes.
  7. wayforkctl: lists, lists set <list> --via <exit> with the usual 60 s auto-revert; rules add … --list <list>.

Open

  • Should the popover show lists at all when there is only one? Draft: hide the section with fewer than two lists.
  • Export/import of a single list (share “Claude” with a colleague without the tunnels). Cheap with this model; not drawn.
  • Windows client: the same model, Fluent UI Expander per list. Design deltas go to 08-windows.md after the macOS version is agreed.
